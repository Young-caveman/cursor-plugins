# How PStack runs on two machines

> **Superseded for the Mac, later on 2026-09-27.** The Mac now tests PStack the way a new user would: the README's user-level install (clone + `npx skills add -g`), done by hand, then its own `/setup-pstack`. The links, the copied pool, and the agent-made install below were removed. Omarchy keeps the linked bench for editing.

As of 2026-09-27 (local time). Explains the setup built that day: why skills are links, which folder to open, how the Omarchy and Mac copies stay in sync, and how the model pool adapts per machine.

## The short version

PStack is a folder of skills. It is edited on Omarchy, published to GitHub, and each machine links those skills into one test copy of Wisdio. T3 runs agents on each machine separately.

| Thing | What it is | Where it lives |
| --- | --- | --- |
| PStack | 47 skills (text files plus a few Python scripts) that tell agents how to work | Your GitHub fork `Young-caveman/cursor-plugins`, folder `pstack/` |
| Wisdio | The app being built, with its own 9 skills | GitHub `Young-caveman/Wisdio` |
| T3 Code | The app that runs agents (Codex, OpenCode, Claude Code) in a project folder | One T3 server per machine |

PStack never becomes part of Wisdio. Wisdio only gets *links* that make PStack's skills visible to agents working in one special copy of Wisdio.

## Why skills are links

Codex, OpenCode and Claude Code only find skills in fixed folders, so PStack's skills have to *appear* in one of those folders. A link (symlink) is a tiny file that says "the real folder is over there".

Where the harnesses look:

- Inside the project: `.agents/skills/` (Codex, OpenCode) and `.claude/skills/` (Claude Code).
- For your whole user account: folders in your home directory. Anything there shows up in *every* project.

There are three ways to make PStack appear, and we picked links:

| Way | Result | Why not |
| --- | --- | --- |
| **Links in one project** (chosen) | One real copy of PStack; the test project shows all 47 skills; editing or updating PStack reaches the project instantly | — |
| Copy the folders into the project | Each project has its own copy | Copies drift apart, and they show up as untracked files in Wisdio's git |
| Install for the user | Every project sees PStack | Normal Wisdio would get PStack too, which you wanted to keep clean |

The links are hidden from git: `pstack_link.py` lists each one by name in `.git/info/exclude`, a local-only ignore file. That's why they never appear in Wisdio's git changes, and why they never travel to GitHub.

The original PStack didn't use links. It was a plugin in Cursor's marketplace (`cursor/plugins`), and Cursor installed and managed it. Codex, OpenCode and Claude Code don't share a plugin system, so this port uses links instead.

## The folders on each machine

For PStack tests, open `Wisdio-pstack` as the T3 project on either machine.

| Folder | Branch | What it's for | Open it in T3? |
| --- | --- | --- | --- |
| Omarchy `/cave/t3-orchestrator-v2-data/worktrees/pstack-source/t3-orchestration` | `t3-orchestration` | PStack source. The only place PStack is edited | Only to work on PStack |
| Omarchy `/cave/Wisdio` | `develop1-engine` | Normal Wisdio work, no PStack | For normal work |
| Omarchy `/cave/Wisdio-pstack` | `pstack-test` | Test copy: Wisdio plus links to the PStack source above | **Yes, for PStack tests** |
| Mac `/Users/jimmy/coding/Wisdio` | `develop1-engine` | Normal Wisdio work, no PStack | For normal work |
| Mac `/Users/jimmy/coding/Wisdio-pstack` | `pstack-test` | Test copy: Wisdio plus links to the installed PStack below | **Yes, for PStack tests** |
| Mac `/Users/jimmy/.local/share/pstack` | `main` | Installed PStack: a clone of your fork, only `pstack/` downloaded. Never edited | No |

Each `Wisdio-pstack` is a *worktree*: a second folder sharing its machine's Wisdio git history, checked out on its own local branch `pstack-test`. That branch is never pushed, so each machine's test copy is its own.

Inside a test copy, the links sit next to Wisdio's own skills:

```
~/coding/Wisdio-pstack/.agents/skills/
  architect         -> ~/.local/share/pstack/pstack/skills/architect   (PStack link)
  setup-pstack      -> ~/.local/share/pstack/pstack/skills/setup-pstack
  ...47 links...
  wisdio-ui-design     (real folder, Wisdio's own skill)
```

There is no folder called `pstack` inside the project. Look for skill names like `setup-pstack` instead.

## Why each machine needs its own install

An agent on Omarchy cannot start or steer agents on the Mac. So the Mac needs PStack installed locally, and a Mac thread has to be opened by you.

This comes from your T3 fork (branch `yash/swiftui-orchestrator-v2-support`, checked in `/cave/t3code`):

- One T3 server is one *environment*. Omarchy's is `cced43fa-…`, the Mac's is `74438402-…` (label "Mac").
- An agent's T3 tools talk only to the server its thread runs on. `delegate_task`, `t3_thread_launch` and `create_threads` have no "which machine" option.
- Your desktop app reaching the Mac over SSH only changes where *you* can open threads. It doesn't let agents cross over.

So a job that needs macOS goes like this:

1. An Omarchy agent does what it can here and writes the Mac part as a task file.
2. You open a thread in `Wisdio-pstack` on the Mac (or ask for Wisdio's `t3-thread-handoff`), and a Mac agent runs it.
3. Results come back through git or through you.

The Mac check on 2026-09-27 confirmed the Mac thread really ran on the Mac: host `Mac.local`, environment `74438402-…`, folder `Wisdio-pstack`.

## How the machines stay in sync

Nothing syncs by itself. Changes move only when they're committed, pushed to GitHub on one machine and pulled on the other.

| What | Travels how | Last synced (2026-09-27) |
| --- | --- | --- |
| Wisdio code | Push `develop1-engine` on one machine, pull on the other | Both at `f1184e1` |
| PStack | Commit on Omarchy, push `main`, then `git pull` in `~/.local/share/pstack` on the Mac | Both at `fada809` |
| A skill PStack generates (e.g. `verify-<app>`) | It's a real Wisdio folder: commit on `pstack-test`, cherry-pick onto `develop1-engine`, push, pull | Nothing generated yet |

What never travels:

- Uncommitted changes.
- The `pstack-test` branches. Each machine keeps its own.
- The links. Each machine makes its own with `pstack_link.py`, pointing at its own PStack path.
- The model pool file. It's per machine (next section).

## The model pool

The pool is the list of models PStack agents may hand work to. Each machine gets its own, built by `/setup-pstack` from what that machine can actually run.

It lives in `~/.config/pstack/models.json`, outside any project. Omarchy's has 8 cheap entries: Luna max, Sonnet 5 at five effort levels, DeepSeek V4.1 Flash, and MiMo V2.6 Pro.

Why per machine: the Mac check showed T3 *lists* Claude as available there, but Claude isn't logged in on the Mac, so a real call failed. A list can't reveal that; only a real call can. Two changes (commit `9fdc6b5`) make PStack adapt:

1. **Setup tests each provider once.** One tiny "reply PONG" call per provider. A provider that fails is left out of that machine's pool, and setup tells you the fix.
2. **Workflows retry provider failures.** If an agent never ran because its provider failed, the workflow reruns it once on another pool model from a different provider, and reports the swap. It never goes outside the pool.

The Mac's file is currently a copy of Omarchy's. Running `/setup-pstack` in a Mac thread replaces it with a tested one. That will also be the first real test of change 1.

## Everyday commands

| When | Where | Do |
| --- | --- | --- |
| Test PStack | Either machine | Open a **new** thread in `Wisdio-pstack` and ask for a skill by name, e.g. "run the setup-pstack skill" |
| PStack was changed on Omarchy | Mac | `git -C ~/.local/share/pstack pull`, then start new threads |
| A skill was added, renamed or removed | Mac | `python3 ~/.local/share/pstack/pstack/skills/setup-pstack/scripts/pstack_link.py --project ~/coding/Wisdio-pstack --harness codex --harness opencode --harness claude --apply` |
| Something looks wrong | Mac | `python3 ~/.local/share/pstack/pstack/skills/setup-pstack/scripts/pstack_doctor.py --project ~/coding/Wisdio-pstack` |
| Which PStack version is installed | Mac | `git -C ~/.local/share/pstack log --oneline -1` |
| See the links | Either | `ls -l ~/coding/Wisdio-pstack/.agents/skills` (Omarchy: `/cave/Wisdio-pstack/.agents/skills`) |
| Before a Mac step | Both | Check both Wisdio folders are at the same commit: `git rev-parse --short HEAD` |
