## How to use during the setup-pstack test

```bash
python3 /cave/pstack-source/pstack/tools/audit-rollout.py list --limit 5
python3 /cave/pstack-source/pstack/tools/audit-rollout.py show <session-id>       # text report
python3 /cave/pstack-source/pstack/tools/audit-rollout.py show <session-id> --json
python3 /cave/pstack-source/pstack/tools/audit-rollout.py follow <session-id>     # live
```

Codex ids are UUID fragments (`01a0…`); OpenCode ids start with `ses_`. `--harness codex|opencode` forces a backend.

Capture per test: harness version, skill invoked, model route actually used (`routing` section), reasoning/variant, tool errors. After `setup-pstack` writes `models.json`, re-run `show` — `NO POLICY MATCH` and `DRIFT` lines are the pass/fail signal.
